# Spec Delta

## Purpose

让窗口尺寸适配可以被自动化地构造、断言与留证：开发者或 CI 能稳定地把应用窗口调成任意目标尺寸，并机械地验证列数、导航形态与分栏结构是否符合该尺寸应得的结果。

## ADDED Requirements

### Requirement: 调试构建提供窗口尺寸注入入口
调试构建 MUST 支持通过启动参数指定目标窗口尺寸（宽 x 高，px），应用启动后 MUST 主动把主窗口调整为该尺寸；发布构建 MUST NOT 因外部启动参数改变窗口尺寸。

#### Scenario: 启动参数触发 resize
- **WHEN** 以 `aa start -a EntryAbility -b <bundle> --ps ohbTestWindow 1400x900` 冷启动调试构建（`--ps` 为"键 空格 值"）
- **THEN** 应用主窗口在页面加载后调整为该内容尺寸，`hidumper` 读到的 WindowRect 为内容尺寸加窗口装饰边（该 PC 上 1400x900 → 1412x966），首页按实测宽度对应的列数渲染

#### Scenario: 发布构建忽略该参数
- **WHEN** 以相同的尺寸参数启动发布构建
- **THEN** 窗口尺寸不受参数影响，保持系统默认

### Requirement: 尺寸注入失败时给出可诊断反馈
当目标尺寸超出系统允许范围或被系统拒绝时，应用 MUST 记录包含请求尺寸与失败原因的日志，MUST NOT 崩溃或阻塞启动。

#### Scenario: 超出范围的尺寸
- **WHEN** 启动参数请求宽度 3000x900，而系统允许的最大宽度为 1920
- **THEN** 应用正常启动，日志中包含被拒绝的请求尺寸与失败原因

### Requirement: 关键尺寸的布局断言分两层可重复执行
测试工程 MUST 提供 ohosTest 用例覆盖断点与列数映射（含 600 / 840 / 1200 的边界值）；UI 层面的尺寸特征（列数、侧边或顶部导航、分栏或堆叠）MUST 由可重复执行的采集流程按稳定 id 断言，因为测试进程无法带参数 force-stop 并重启被测应用。

#### Scenario: 断点边界用例
- **WHEN** 运行 ohosTest 的 `WindowLayoutBreakpoints` 套件
- **THEN** 599.9 / 600 / 839.9 / 840 / 1199.9 / 1200 各得对应 SizeClass、列数与 `isWide` 结果，用例全部通过

#### Scenario: 首页列数断言
- **WHEN** 采集流程把窗口调整到 1600px 宽并等待布局稳定
- **THEN** 流程按 `home_feed` 首行子节点数断言列数等于实测宽度对应的列数

#### Scenario: 视频页分栏断言
- **WHEN** 采集流程把视频页窗口调整到 ≥840vp 对应的宽度
- **THEN** 流程断言 `video_related` 与 `video_comments` 同时存在且位于不同水平区域，窄尺寸下两者不同时出现

### Requirement: 关键布局节点具备稳定标识
参与布局断言的节点 MUST 具备稳定的、与尺寸无关的标识（如组件 id），使测试无需依赖文案或坐标即可定位。

#### Scenario: 不同语言下断言仍成立
- **WHEN** 系统语言切换为英文后重复执行列数与分栏断言
- **THEN** 用例使用节点标识定位成功，断言结果与中文环境一致

### Requirement: 外部窗口拖拽作为兜底验证通道
当应用内尺寸注入不可用时，验证流程 MUST 能够通过系统级拖拽调整窗口尺寸，并按实测窗口矩形闭环修正；每次调整后 MUST 读取实际矩形与预期尺寸比对，不满足容差时 MUST 重试或标记失败，且布局断言 MUST 以实测宽度为准而非目标宽度。

#### Scenario: 拖拽后校验实际尺寸
- **WHEN** 通过系统级拖拽把窗口拉宽到目标宽度
- **THEN** 流程读取窗口实际矩形，确认宽度进入容差后才继续断言布局

#### Scenario: 拖拽未达标
- **WHEN** 拖拽后读取到的窗口宽度与目标相差超过容差
- **THEN** 流程记录该尺寸为失败而非照常继续，避免把错误尺寸下的截图当作证据

#### Scenario: 拖拽精度下限
- **WHEN** 残余误差已小于该设备拖拽热区可分辨的下限（实测约 60px）
- **THEN** 流程停止继续拖拽，改用实测宽度计算期望列数后再断言，并在日志中说明已达精度下限

### Requirement: 尺寸矩阵批量采集
项目 MUST 提供一个可重复执行的采集脚本：对预定义的尺寸矩阵逐个启动应用、采集截图与布局树，并按尺寸命名输出，便于回归对比。

#### Scenario: 生成尺寸矩阵证据
- **WHEN** 执行采集脚本
- **THEN** 输出目录中每个尺寸都有对应的截图与布局树文件，文件名包含尺寸信息

### Requirement: 设备连接中断可自愈
自动化流程 MUST 在设备连接丢失时自动重连并重试当前步骤，MUST NOT 因单次连接失败中止整个矩阵采集。

#### Scenario: 连接断开后继续采集
- **WHEN** 采集中途设备连接中断
- **THEN** 流程重连成功后继续剩余尺寸的采集，且最终报告中标记发生过重连
